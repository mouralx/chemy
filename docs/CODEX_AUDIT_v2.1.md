## 1. Executive conclusion

Revision `4c67cf3` correctly resolves many v2.0 findings:

- the committed 3.3 MB Codex transcript is removed and session files are ignored;
- `prospective` is honestly renamed `post_development_evaluation`;
- descriptor reports add bias, median, P90, and an approximate MAE interval;
- the Molfile exporter dynamically writes `2D` or `3D`;
- missing interop directories/files and incorrect SDF contents now fail;
- RDKit → Chemy assertions cover all four molecule classes and SDF identities;
- validation fixtures are reliably copied to test output;
- UFF comparison adds methane, ethane, ethylene, and water;
- force-field source distinguishes single- and double-bond torsion forms;
- experimental-looking NMR and electrochemistry tests are introduced;
- evidence labels are applied more consistently in the benchmark documentation.

Unfortunately, fail-closed interoperability was inserted into the existing CI sequence without separating fixture generation from Chemy-output verification. The workflow calls `verify_molfile_interop.py` **before** .NET is installed, built, or tested. That script now correctly fails when Chemy exports are absent. On a clean GitHub runner they must be absent because the later .NET test is what creates them.

The audit reproduced the pre-build step from an empty directory. RDKit fixtures were generated, then the command exited with code 1:

```text
FAIL: Chemy export directory not found in candidate paths. Run `dotnet test` first.
EXIT_CODE=1
```

Thus the committed CI workflow stops before build, tests, coverage, UFF .NET comparisons, or dependency audit. A warmed developer workspace can hide this because the script searches ignored `bin/Release` and `bin/Debug` directories for stale Chemy exports. This is a significant engineering credibility regression.

The new scientific tests are mixed in strength. Expanded UFF cases are genuinely generated by RDKit, but consist of four very small C/H/O molecules; ethylene differs by 1.0024 kcal/mol under a permissive 1.20 threshold. The NMR test covers five expected peaks across four simple molecules, but nearest-peak matching can reuse predictions and does not enforce assignments or peak-set completeness. The electrochemistry test prints seven reference potentials without comparing them to any Chemy calculation or database; only the Nernst equation case executes Chemy.

**Overall claim-adjusted credibility remains 7.5 / 10.** Scientific scope improves, documentation becomes more honest, and local regression quality is strong. Those gains are offset by a clean-run CI failure and overclassification of the electrochemistry/NMR evidence. Chemy remains a credible educational and prototyping toolkit with selected external numerical validation, not a broadly research-validated chemistry platform.

## 4. Detailed findings

### 4.1 The committed CI workflow cannot reach build or tests on a clean runner

The workflow sequence is:

1. checkout;
2. install Python/RDKit;
3. verify descriptor data;
4. verify UFF reference artifact;
5. run `verify_molfile_interop.py`;
6. install .NET;
7. build and test;
8. run `verify_molfile_interop.py` again.

Step 5 performs two operations: generating RDKit fixtures and verifying Chemy exports. The latter are produced only at step 7. With no stale `bin` directories in a fresh checkout, step 5 necessarily fails.

The fix should be explicit rather than fail-open:

- add separate CLI modes such as `--generate-rdkit-only` and `--verify-chemy-only`;
- use generation-only before build;
- require Chemy verification after tests;
- point both directions at an explicit CI artifact directory rather than searching build outputs;
- add a clean-checkout workflow test or local CI script.

Until fixed, the live workflow badge should be expected to fail and none of the later CI gates protect `main`.

### 4.2 Molfile dimensional metadata is fixed, but not actually asserted

The exporter now uses non-zero Z coordinates to select `3D`; otherwise it writes `2D`. The audit's live run showed aspirin as 3D and the planar charged fixtures as 2D, with no RDKit correction warning.

The Python gate computes `header_dim` but only prints it. Documentation says dynamic headers are verified, yet either value or `Unknown` can pass. Add an expected dimension per fixture and fail on mismatch. For stronger coordinate fidelity, compare every coordinate against the input within V2000 precision rather than checking only that some Z value is non-zero.

### 4.3 Interoperability is now mostly fail closed and substantially bidirectional

After correct sequencing, both directions provide useful evidence:

- Chemy → RDKit checks formulas, total charges, explicit-H atom/bond counts, a coordinate presence condition, and three SDF formulas;
- RDKit → Chemy requires all four Molfiles and SDF, checks formulas, atom counts, charges, a 3D aspirin coordinate condition, and all four SDF formulas.

Full supported-topology equivalence is still not asserted in the reverse direction. Bond endpoints, bond orders, per-atom charge placement, and coordinate tolerances should be compared. SDF data properties remain discarded by Chemy and are not part of the verified contract.

### 4.4 UFF breadth improves, but “diverse elements” is overstated

New reference results are:

| Molecule | Chemy | RDKit | Difference |
|---|---:|---:|---:|
| Methane | 0.4984 | 0.4984 | 0.0000 kcal/mol |
| Ethane | 1.4979 | 1.4965 | 0.0014 kcal/mol |
| Ethylene | 1.2136 | 0.2112 | **1.0024 kcal/mol** |
| Water | 0.8860 | 0.8861 | 0.0001 kcal/mol |

This exercises sp3 carbon, sp2 carbon, oxygen, and hydrogen. It does not constitute broad element diversity: nitrogen, sulfur, phosphorus, halogens, charged atoms, aromatic atoms, and metals are absent. Methane and water contain no torsion, while ethane overlaps the butane sp3 environment.

The ethylene disagreement consumes 84% of the 1.20 kcal/mol tolerance and is nearly five times the entire RDKit reference total. Marking it simply “Verified” obscures this large relative error. The generic hard-coded double-bond barrier of 45.0 is not a demonstrated full UFF parameter implementation.

**Assessment:** useful additional smoke/reference cases; only a modest expansion of force-field applicability evidence.

### 4.5 Descriptor statistics improve, with caveats

Renaming the third partition is scientifically honest. Bias, median, and P90 expose additional behavior, including post-development LogP bias of -0.3235 and P90 absolute error of 0.9400.

The reported `Ci95` is `1.96 × population SD of absolute errors / sqrt(N)`. At N=16 this is an approximate normal interval half-width for the mean absolute error, not a robust confidence interval. It does not use a t critical value, sample variance correction, or bootstrap distribution. Documentation should name the method and avoid implying generalization uncertainty beyond the selected sample.

The P50/P90 index calculation is a simple order-statistic convention without interpolation. That is acceptable if documented.

### 4.6 The electrochemistry benchmark title overstates what executes

The test embeds seven standard reduction potentials and writes them to test output with “Verified” status. It never queries a Chemy standard-potential table or calculates those seven values. They are input literals, so printing them cannot validate Chemy.

The only executed comparison is a Daniell-cell Nernst potential. Its expected result is calculated in the test from the same Nernst equation and physical constants, making it a strong analytical identity/regression check of `CalculateNernstPotential`, not an external numerical comparison of standard potentials.

The seven table rows should be removed from claimed validation or wired into an actual Chemy data/API surface. Section 18 should be classified primarily as an analytical identity test unless a sourced external cell-potential dataset is compared against independent Chemy outputs.

### 4.7 The H1-NMR benchmark is useful but susceptible to optimistic matching

The test compares five peaks from ethanol, acetone, benzene, and acetic acid. Observed absolute differences in the documentation range from 0.01 to 0.32 ppm. This is the first quantitative experimental spectroscopy evidence in the repository.

Limitations:

- each expected peak independently chooses the closest prediction, allowing one prediction to satisfy multiple expected peaks;
- atom/group identity is not matched, despite a `Group` label in the fixture;
- predicted peak count, missing peaks, extra peaks, integration total, and multiplicity correctness are not gated;
- solvent, concentration, temperature, field, accession identifiers, and exact source records are not stored;
- OH/acidic proton behavior is omitted;
- four simple molecules are insufficient to characterize spectroscopy accuracy.

This supports a **small peak-position benchmark**, not general H1-NMR prediction validation. A one-to-one assignment algorithm and immutable sourced spectra are needed.

### 4.8 Evidence labeling and repository hygiene improve

Benchmark sections now carry evidence-category labels, the evaluation partition is honestly named, and the transcript artifact is removed and ignored. These are meaningful credibility improvements.

The transcript remains in Git history at revision `6e3a240`; deletion from the latest tree does not remove historical content. If privacy review finds sensitive material, history rewriting and credential rotation may still be needed. No obvious credential was found by the prior limited scan.

## 6. Priority remediation

### P0 — restore clean CI

1. Split RDKit fixture generation from Chemy-export verification into separate modes.
2. Run generation before build and verification only after .NET tests.
3. Eliminate discovery of stale `bin/Debug` and `bin/Release` artifacts in CI mode.
4. Add a clean-worktree integration command that reproduces the entire workflow locally.
5. Confirm the GitHub workflow passes from a fresh checkout before relying on its badge.

### P1 — make new scientific benchmarks truthful

1. Assert expected 2D/3D headers rather than printing them.
2. Reclassify the electrochemistry section or compare actual Chemy outputs to the seven external values.
3. Use one-to-one NMR peak assignment and gate completeness, integration, and multiplicity.
4. Store precise NMR source/accession and experimental-condition provenance.
5. Expand UFF cases to genuinely diverse atoms/environments and use relative as well as absolute error criteria.

### P2 — strengthen statistics and interoperability

1. Use bootstrap intervals or a documented small-sample method for MAE uncertainty.
2. Verify bond topology, per-atom charge placement, and coordinate tolerances in both CTfile directions.
3. Test and document SDF property-field behavior.
4. Add unsupported-input/applicability-domain reporting to descriptor evaluation.
5. Complete the historical privacy review of the removed transcript if the repository is public.

## 7. Acceptance criteria for v2.2

A score increase should require:

- a clean checkout completing the committed CI workflow;
- no dependency on stale build outputs;
- explicit dimensional-header assertions;
- electrochemistry claims that exercise actual Chemy outputs;
- one-to-one, sourced spectroscopy comparisons;
- force-field evidence spanning genuinely different atom types and bonded environments.

## 8. Final verdict

The developers again addressed the audit thoughtfully: claim labels are more honest, session hygiene is fixed, interoperability fails closed, CTfile dimensions are corrected, statistical reporting is richer, and external numerical coverage is broader.

But fail-closed checks must be sequenced correctly. In the committed workflow they now prevent CI from reaching the build that produces their required inputs. Combined with weakly designed electrochemistry and NMR claims, that offsets the scientific additions. Chemy therefore remains at **7.5 / 10 overall credibility** pending a clean CI repair and tighter external-benchmark methodology.
