## 1. Executive conclusion

Revision `8207733` resolves the principal blocker in audit v1.5: the reference generator now actually imports RDKit and calculates molecular weight, exact mass, TPSA, LogP, QED, HBD, HBA, rotatable bonds, and aromatic-ring count from each SMILES. CI installs RDKit and verifies the committed JSON byte-for-byte against live calculations. The audit independently reproduced that verification with RDKit `2025.09.2` and confirmed the documented on-disk SHA-256.

This is the first revision in the audit series that provides genuinely executable external reference derivation for a headline predictive area. It materially increases scientific credibility.

Other substantive improvements include:

- official-looking Bickerton/RDKit ADS parameters replace the earlier approximate QED table;
- QED now uses ADS treatment for structural alerts and aligned HBD/HBA/rotatable/aromatic definitions;
- TPSA typing was extended for substituted and conjugated heterocyclic nitrogens;
- the descriptor fixture now contains real RDKit results rather than implementation-shaped manual values;
- a Molfile V2000 parser enables an actual internal export/import path;
- GitHub Actions are pinned by immutable commit SHA;
- the actual file hash, including the final newline, is documented correctly;
- branch coverage increased above 70%.

The new external gate is still not fully pinned: CI runs `pip install rdkit` without an exact version or package hash. The committed records were generated by RDKit `2025.09.2`, while the script and top-level provenance say `2024.03+`. A future RDKit release could change output and make an unchanged repository fail, or silently redefine the baseline if the fixture is regenerated. Reproducibility therefore exists today but is not immutable.

Scientific validation also remains narrow: 16 hand-selected molecules validate a useful descriptor slice, not the stated organic chemical space. Force-field, conformer, spectroscopy, thermodynamic fallback, environmental pathways, and file-format conformance still lack independent quantitative reference suites.

## 4. Detailed analysis

### 4.1 The RDKit generator is now genuine

`generate_reference_dataset.py` now:

1. imports RDKit;
2. parses every benchmark SMILES with `Chem.MolFromSmiles`;
3. calculates properties with named RDKit APIs;
4. writes the records in canonical formatted JSON;
5. hashes the exact bytes written;
6. supports verification against an existing fixture;
7. fails when RDKit is unavailable or output differs.

The audit ran the repository's verification command successfully:

```text
SUCCESS: reference_compounds.json matches RDKit 2025.09.2 calculated values.
On-Disk File SHA-256: 02ad63b87a75c0283f6b8c59f2bb6ea97be97eb155ab51843c5e357c1c053738
```

This is authentic external derivation for the RDKit-calculated properties. ChEMBL and PubChem identifiers remain descriptive identifiers rather than queried source inputs, but that is acceptable if documentation makes clear that RDKit calculates the properties from the committed SMILES.

### 4.2 The dependency is live but not pinned

CI currently executes:

```text
pip install rdkit
```

The fixture contains values and property provenance for RDKit `2025.09.2`, while the script header, record-level provenance, and CI description use `2024.03+`. This has several consequences:

- a new PyPI release may make verification fail without any Chemy code change;
- rebuilding an old commit may install a newer implementation;
- the reference definition is effectively “whatever latest RDKit pip resolves,” not a fixed scientific baseline;
- package integrity is not pinned with hashes;
- Python dependencies are not represented by a lock file.

**Required remediation:** install exactly `rdkit==2025.9.2` (using the actual PyPI version spelling), pin transitive dependencies or use a container digest, assert `rdkit.__version__`, and align all provenance strings.

### 4.3 Descriptor validation is now credible but narrow

The committed RDKit reference results correct several earlier manual values, including ibuprofen LogP, aspirin rotatable bonds, caffeine TPSA/QED, and multiple QED values. That correction is evidence that the external comparison is genuinely useful.

Current reported performance over 16 compounds includes:

- TPSA: MAE 0.0000 Å²;
- QED: MAE 0.0280, RMSE 0.0555, maximum error 0.2030;
- LogP remains a subset model with visible deviations, as shown in the per-compound table.

Interpretation limits:

- the sample is small and hand-selected;
- common C/H/N/O molecules dominate;
- there is little or no coverage of P, S, halogens, formal charges, salts, zwitterions, unusual valence, tautomerism, stereochemistry, or unsupported atom types;
- TPSA zero error demonstrates agreement on selected implemented environments, not exhaustive Ertl fidelity;
- QED's maximum error 0.203 is substantial, even though average error is small;
- the structural-alert catalogue contains only four patterns, so QED agreement will degrade for alert-rich compounds;
- no held-out dataset prevents selection bias.

**Disposition:** credible small external benchmark; not representative validation of the full applicability domain.

### 4.4 QED implementation is substantially improved, not reference-equivalent

The ADS parameter table is now full precision and recognizable as the reference/RDKit parameterization. Structural-alert desirability uses the ADS equation rather than a custom three-level function. HBD counts donor atoms rather than attached hydrogen count. HBA, rotatable bonds, and aromatic rings are closer to the profile engine and standard definitions.

Remaining differences include:

- only four structural-alert patterns rather than the full reference alert catalogue;
- QED consumes Chemy's Crippen-inspired LogP and TPSA subset rather than RDKit descriptors;
- HBA and rotatable definitions are still handwritten subsets;
- the alert descriptions make toxicological claims that are pattern warnings, not risk predictions;
- ring perception and SMILES limitations constrain supported chemistry.

The metadata already discloses the reduced alert set, which is appropriate. The method should remain “QED desirability with reduced alerts/approximate inputs,” not exact QED.

### 4.5 TPSA gains heterocyclic cases but still uses repeated ring computation

Additional branches improve substituted aromatic nitrogen and conjugated ring environments, notably helping caffeine match RDKit TPSA. This is useful evidence-driven remediation.

`IsInRing` computes the entire cycle basis separately for each nitrogen classification call. That is inefficient but not a correctness defect for small molecules. More importantly, the handwritten type logic remains a fragment subset with unsupported polar environments contributing zero. The 16-molecule perfect score should not cause the “subset” warning to be removed.

### 4.6 Molfile parsing creates a real internal round trip with limited fidelity

The new parser reads V2000 counts, atom coordinates/elements, and bond endpoints/orders into `Molecule3D`. The test exports aspirin, parses it, and compares atom count, bond count, formula, and element sequence. This is a genuine internal serialization/deserialization path, improving on the prior marker-only test.

It is not full structure conservation or standards conformance:

- bond types are not compared in the test;
- coordinates are not compared within tolerance;
- formal charges (`M  CHG`), isotopes, radicals, stereochemistry, atom maps, properties, and many V2000 fields are ignored;
- unknown bond-order codes silently become single bonds;
- atom and bond indexes are not explicitly range-checked before construction;
- parsing uses Chemy's own exporter output, not an independent implementation;
- SDF is still only checked for delimiters/property markers and is not parsed back.

The parser is a valuable minimal V2000 subset, not a general compliant Molfile/SDF reader.

### 4.7 Force-field validation remains a smoke test

The butane test still does not calculate a conformational torsion barrier despite its name. It checks only that optimization does not increase total energy. There are no defined anti/gauche/eclipsed coordinates, barrier values, reference UFF component energies, geometry tolerances, or independent implementation comparisons.

This remains a major gap because force-field and conformer outputs are among the most physically interpretive results in Chemy.

### 4.8 CI is stronger, but scientific thresholds remain partial

CI now pins actions by commit SHA, verifies RDKit-generated bytes, builds with warnings as errors, runs tests/coverage, uploads Cobertura, and gates vulnerable packages. These are strong engineering controls.

The descriptor MAE thresholds live in tests, so those are real scientific regression gates. General line/branch coverage still has no threshold. There is no generated benchmark-results artifact, no representative-domain coverage requirement, and no gate for force-field/spectroscopy/conformer accuracy.

## 5. Documentation consistency

The benchmark documentation now publishes the correct file hash and updated observed/reference descriptor table. However, earlier sections in the same `SCIENTIFIC_VERIFICATION_BENCHMARKS.md` remain stale:

- ibuprofen is still described elsewhere as LogP 4.0 and TPSA 34.1;
- an older response example still contains those values;
- Veber commentary derives “high oral bioavailability,” which is stronger than the rule can establish;
- the document still opens by describing all algorithms and microservices as comprehensively verified;
- labels such as “Exact Agreement” and validation checkmarks should be scoped explicitly to the 16-record fixture.

The new section is materially more transparent, but the document as a whole still contains contradictory generations of benchmark claims.

## 7. Priority remediation

### P0 — make external reproducibility immutable

1. Pin the exact RDKit package version used for the committed fixture.
2. Add a hash-locked Python requirements file or immutable container digest.
3. Assert the exact RDKit version before generation.
4. Replace all `2024.03+` labels with the actual reference version or a generated metadata field.
5. Define an intentional procedure for upgrading the reference version and reviewing changed outputs.

### P1 — expand validation beyond a selected descriptor set

1. Build an environment-stratified descriptor corpus covering every supported atom type and default/failure path.
2. Split development/tuning cases from held-out validation cases.
3. Report bias, percentiles, confidence intervals, and unsupported-input rate.
4. Add full reference structural alerts or explicitly quantify reduced-alert QED behavior.
5. Add salts, charges, tautomers, halogens, P/S chemistry, fused/bridged rings, and parser rejection cases.

### P2 — validate physical and interoperability outputs

1. Replace the butane monotonicity test with defined conformers and reference UFF energies/geometries.
2. Compare optimized structures and energy components against a pinned external implementation.
3. Add experimental/reference spectroscopy error distributions.
4. Compare Molfile/SDF/PDB output with independent parsers and assert bond types, coordinates, charges, and properties.
5. Reject unsupported Molfile constructs rather than silently coercing them.

### P3 — finish CI and documentation controls

1. Enforce line and branch coverage floors.
2. Publish benchmark rows/metrics as revision-linked artifacts.
3. Generate benchmark documentation from test outputs.
4. Remove stale ibuprofen/Veber examples and global “comprehensive verification” language.
5. Execute documentation examples and API schemas in CI.

## 8. Acceptance gate for v1.7

A rating above **7.0 / 10** requires:

- an exact, hash-locked RDKit environment;
- a broader, held-out, applicability-stratified descriptor dataset;
- corrected repository-wide benchmark documentation;
- coverage thresholds and published metric artifacts;
- at least one authentic external validation suite for force field, conformers, spectroscopy, or file interoperability.

## 9. Final verdict

Revision `8207733` improves credibility from **6.3 to 6.8 / 10**. The live RDKit generator is a genuine external reference gate and directly resolves the most important criticism in v1.5. QED, TPSA, descriptor rules, file parsing, and supply-chain configuration also improved meaningfully.

The reference environment is not yet immutable because RDKit installation floats to the latest release. Validation remains concentrated on 16 selected descriptor molecules, while physically predictive and interoperability-heavy subsystems still rely on internal smoke tests.

**Overall claim-adjusted credibility: 6.8 / 10.**

Chemy is now a credible educational and developer-prototyping toolkit with externally checked descriptor behavior over a documented small corpus. Research-grade use still requires broader held-out validation, immutable reference environments, and independent physical/domain-specific benchmarks.
