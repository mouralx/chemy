## 1. Executive conclusion

Revision `060f555` is a real improvement, but it does not yet deliver all that its new labels imply.

The strongest changes are reproducibility and regression breadth. The RDKit environment is now pinned to exact package versions, the generator rejects any RDKit version other than `2025.09.2`, and the committed 32-record file reproduces byte-for-byte. Descriptor coverage now includes halogens, sulfur, phosphorus, aromatic heterocycles, and polycyclic systems. CI also enforces an 80% line-coverage floor. The Molfile reader now rejects invalid bond endpoints and unsupported bond-order codes, and tests compare coordinates and bond topology.

Two headline additions are overstated:

- The 16 records called **held-out** are not a defensible held-out validation set. The same revision adds them and changes TPSA, HBA, QED, and SMILES behavior specifically for chemical environments represented by those records. The tests calculate only one aggregate result over all 32 records; the declared tuning and held-out lists are not separately evaluated. This is a larger development/regression set, not prospective or blind validation.
- The claimed **physical butane torsion barrier** is not physically credible. Every hydrogen in every conformer is placed at `(0, 0, 0)`. Those collapsed coordinates introduce extreme, artificial bonded and non-bonded contributions. The test checks ordering generated by Chemy's own force field and no external or experimental barrier values. It cannot validate physical conformer energetics.

The exact-version dependency file improves repeatability but is not hash-locked, so package artifacts are still mutable at the supply-chain level. The parser's XML documentation claims formal-charge reconstruction although no Molfile charge field or `M  CHG` record is parsed. The README badge says 147 tests passed, while the audited run executes 146.

**Overall claim-adjusted credibility: 6.9 / 10**, up from 6.8. Chemy remains credible for education, demonstrations, and developer prototyping within its documented subsets. It now has a better descriptor regression corpus, but it still lacks independent validation for research-grade physical predictions, broad chemical-space generalization, spectroscopy, thermodynamic fallbacks, environmental pathways, and file-format conformance.

## 4. Detailed findings

### 4.1 RDKit derivation is version reproducible, not artifact immutable

`scripts/requirements-reference.txt` fixes RDKit, NumPy, and Pillow versions. The generator asserts the exact RDKit runtime version before calculating data. CI installs that file and verifies the JSON byte-for-byte. Local verification succeeded for all 32 records.

This closes the floating-version defect from v1.6. It does not meet the earlier request for a hash-locked environment: pip may obtain any artifact published under those version identifiers, and there are no hashes for wheel integrity. The comment also claims macOS/Linux and x86-64/arm64 coverage without a CI matrix proving all combinations.

**Assessment:** strong scientific repeatability improvement; incomplete supply-chain immutability.

### 4.2 The expanded set is useful but is not held out

The extra compounds materially improve regression coverage. They expose the parser and descriptor engines to aromatic oxygen, `[nH]`, sulfur oxidation states, phosphorus, halogens, and fused rings.

However, a holdout must be separated from model development and remain unseen while rules or parameters are selected. In this revision:

- the records and their `held_out` labels are introduced together with implementation changes;
- TPSA branches are added for aromatic oxygen and sulfur/phosphorus environments represented in the new set;
- HBA/QED behavior is changed for acidic oxygen, sulfur/phosphorus attachment, and pyrrolic nitrogen represented in the set;
- SMILES parsing is modified for aromatic bracket atoms and related valence/ring behavior;
- `Benchmark_StatisticalDistribution` creates `tuningSet` and `heldOutSet` variables but computes MAE, RMSE, maxima, and acceptance tests over the combined dataset only.

Therefore the reported 32-record values are **in-sample regression metrics**. They do not estimate generalization performance. Calling the second half “held-out” creates more confidence than the experiment supports.

To establish a defensible holdout, freeze a test manifest and hashes now, prohibit model authors from using its results while changing algorithms, and publish separate tuning and holdout metrics in a later revision. A stronger option is an external evaluation corpus selected and executed by an independent maintainer.

### 4.3 Descriptor results are broader, but exact TPSA is bounded evidence

Published combined metrics are:

| Property | MAE | RMSE | Maximum error | Test threshold |
|---|---:|---:|---:|---:|
| TPSA | 0.0000 Å² | 0.0000 Å² | 0.0000 Å² | MAE < 0.05 Å² |
| LogP | 0.2121 | 0.2699 | 0.6320 | MAE < 0.35 |
| QED | 0.0195 | 0.0412 | 0.2030 | MAE < 0.10 |

These are useful and honestly show that LogP and QED are approximations. TPSA's zero error means the handwritten rules reproduce RDKit for these selected environments. It does not prove full Ertl implementation equivalence, especially for charged species, salts, uncommon valences, organometallics, or unrepresented atom types.

The thresholds constrain only mean error. There is no maximum-error, percentile, bias, unsupported-input-rate, or per-subset gate. In particular, a QED maximum deviation of 0.203 is meaningful even though mean error passes.

### 4.4 The butane benchmark does not validate a physical barrier

The new test constructs four carbon skeletons named anti, gauche, eclipsed, and syn-eclipsed. It then assigns every hydrogen in each molecule to the origin. This invalidates the energy comparison: bond stretching, angles, and interatomic distances are dominated by impossible hydrogen geometry rather than a controlled C–C torsion.

Additional validity gaps are:

- the test does not calculate the actual C–C–C–C dihedral from coordinates;
- conformers do not share a validated, fixed bond-length/angle construction;
- reported energies are not compared with pinned RDKit UFF, another implementation, or experimental barriers;
- expected inequalities are derived from chemical intuition, not numerical reference tolerances;
- only the syn structure is minimized, so optimization behavior is not compared consistently.

The passing result is at most an internal regression of energy ordering for malformed inputs. It must not be presented as a “physical conformational torsion barrier.” This finding prevents a larger increase in the scientific credibility score.

### 4.5 Molfile/SDF behavior is safer but narrower than its contract

Positive changes include endpoint range validation, explicit rejection of unknown bond orders, coordinate-tolerance comparison, bond-type/end-point comparison, and multi-record SDF parsing tests.

The reader remains a narrow V2000 subset:

- it never parses atom-block charge codes or `M  CHG` records, despite its XML summary claiming reconstruction of formal charges;
- isotope, radical, stereo, valence, atom-map, and query fields are ignored;
- SDF data fields are discarded;
- records without `M  END` are silently omitted by `FromSdf` rather than rejected;
- validation uses Chemy's exporter and importer, allowing reciprocal mistakes to pass;
- no external toolkit reads Chemy output and no independent fixture exercises the supported contract.

The immediate fix is to narrow the XML contract or implement charges and explicit rejection of unsupported fields. Research-grade interoperability requires independent conformance fixtures or cross-tool validation.

### 4.6 CI enforcement improved, with fragile and incomplete edges

CI now enforces the 80% line threshold and current local coverage clears it by 0.85 percentage points. This is a useful regression control. Branch coverage is 72.26% but has no enforced floor.

The ReportGenerator tool installation is floating and uses `|| true`. Pinning its version in a tool manifest would make CI deterministic. The parsing step relies on English summary text and `bc` availability rather than reading Cobertura XML with a repository-controlled script. Neither issue invalidates current results, but both make the gate less portable and reproducible than the RDKit gate.

### 4.7 Documentation is improved but not fully synchronized

The benchmark documentation accurately publishes the 32 rows, combined metrics, exact RDKit version, and current reference hash. Remaining claim mismatches include:

- README badge: **147 passed**; audited current result: **146 passed**;
- parser documentation: formal charges reconstructed; implementation: charges not read;
- “held-out validation” wording: no independent holdout procedure or separate evaluation;
- “physical energy ordering/torsion barrier” wording: malformed hydrogen coordinates and no external physical values;
- an absolute local `file:///Users/...` link in scientific documentation, which will not work for other developers.

## 6. Priority remediation

### P0 — correct validation claims

1. Rename `held_out` to `expanded_regression` until a genuinely frozen evaluation is performed.
2. Report tuning and future holdout metrics independently; remove unused split variables.
3. Replace the butane test with chemically complete coordinates, computed dihedrals, and pinned external reference energies.
4. Remove the formal-charge parser claim or implement/test V2000 charge handling.
5. Update the README test badge to an automatically generated or non-numeric badge.

### P1 — establish independent scientific validation

1. Freeze a larger environment-stratified corpus in advance of the next model changes.
2. Add per-subset bias, MAE/RMSE, percentiles, maxima, confidence intervals, and rejection rates.
3. Compare UFF energy components, optimized geometries, and torsional scans against a pinned external implementation.
4. Add independent spectroscopy references and thermodynamics fallback benchmarks.
5. Validate Molfile/SDF output bidirectionally with an external parser and charged/stereo fixtures.

### P2 — finish reproducibility and CI controls

1. Hash-lock Python wheels per supported platform or use a container image pinned by digest.
2. Pin ReportGenerator with a repository tool manifest.
3. Enforce a branch-coverage floor as well as line coverage.
4. Parse coverage using a controlled script and fail explicitly on missing/malformed values.
5. Add CI jobs for every platform/architecture claimed by the reference requirements comment.

## 7. Acceptance criteria for v1.8

A future audit should require all of the following before materially increasing research credibility:

- an evaluation set demonstrably frozen before subsequent algorithm changes, with separate published results;
- chemically valid butane conformers and numerical external energy/geometry tolerances;
- hash-locked reference dependencies or an immutable container digest;
- truthful and tested parser scope, including explicit charge behavior;
- line and branch CI thresholds with pinned tooling;
- at least one independent quantitative benchmark outside the descriptor family.

## 8. Final verdict

The developers have improved Chemy's engineering controls and expanded the useful domain of its descriptor regression tests. Exact RDKit version enforcement, the larger corpus, safer parsing, and a real coverage floor all deserve credit.

The evidence still supports **education and prototyping**, not publication-grade or decision-grade scientific prediction. The largest credibility risk in this revision is no longer absence of tests; it is assigning scientific labels—“held-out” and “physical barrier”—to tests whose experimental design does not support those labels. Correcting that distinction, then adding genuinely independent evaluation, is the shortest path to a substantially higher score.
